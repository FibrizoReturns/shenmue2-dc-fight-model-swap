## 1. 先分清两条链：我方 ≠ 对手

这是整套工程最容易搞错的地方。玩家的凉和格斗对手，走的是两套完全独立的加载路径。

| 身份 | 载体 | 关键文件 |
|---|---|---|
| **我方**（玩家操纵） | 玩家槽三件套 | `SCENE\04\MODEL\CHARA\RYO_M.MT7` + `SCENE\04\MODEL\HAND\RYO_TL.MT7` / `RYO_TR.MT7` |
| **对手**（1~11 格） | 各格 EV3 里改代号 → 落到 AFS 模型 | `SCENE\04\<场地>\SFxx.EV3` 里的 `D05_/KSM_/WON_…` 代号 + `HUMANS.AFS` |
| **对手**（12 格） | 引擎硬编码 | `HUMANS.AFS` item 1736/1737（`TGY_` 斗牛），改不动 |

- 换我方：只动 `RYO_M.MT7`（双手可选）。
- 换对手：只动各格 `SFxx.EV3` 的代号（必要时才动 AFS / TGLB / QFRR）。

## 2. 核心结论：幻彩是怎么来的

**玩家槽只读三个文件，引擎不会去旁边找这个角色的贴图包。**

```
SCENE\04\MODEL\CHARA\RYO_M.MT7                 ← 身体：决定"谁"，而且贴图必须装在它内部
SCENE\04\MODEL\HAND\RYO_TL.MT7 / RYO_TR.MT7    ← 双手
```

所以把「裸网格」直接写进去，就是整身彩色噪点（下文统称「幻彩」）。模型块构成对照：

| 模型 | 大小 | MDC7 | FACE | CLSG | TXT7 | PVRT | 实机 |
|---|---|---|---|---|---|---|---|
| RYO 原版 | 291,824 | 93,760 | 8,160 | 3,040 | 186,864 | 11 | 正常 |
| 少年凉（成品） | 202,420 | 63,968 | 5,920 | 1,184 | 131,348 | 6 | 正常 |
| 高野泉（成品） | 232,244 | 87,840 | 10,624 | 2,432 | 131,348 | 6 | 正常 |
| LRY 裸网格 | 71,072 | 63,968 | 5,920 | 1,184 | **无** | 0 | 幻彩 |
| XGH 裸网格 | 100,896 | 87,840 | 10,624 | 2,432 | **无** | 0 | 幻彩 |

关键观察：**少年凉、高野泉的网格部分与各自的裸网格逐字节相同**，差别只在后面那段 `TXT7`。也就是说，决定「花不花」的唯一变量就是 TXT7 在不在、对不对。

> 反过来用：想复现幻彩，把 AFS 里取出的 CHRM 正文原样写进 `RYO_M.MT7` 就行，一步到位，必然花。

## 3. 手工拼 TXT7：正版精确格式

两条替代路线：① 直接用替换器成品（推荐，见 §5）；② 自己把网格 + 贴图拼成完整模型。走 ② 的话，TXT7 必须严格按下面布局，错一个字节也照样花。

```
+0      'TXT7'
+4      u32 size   = 整个 TXT7 长度
+8      u32 cnt    = 网格节点数（网格头 +0x0C 处）
+12     u32 offsets[cnt]    首项 = 84，全部以 TXT7 起点为基准
+12+4n  8×cnt 字节名字表（从网格 0x10+cnt*16 处原样搬，形如 \x95PC_AUA_）
+84     贴图块 × cnt
```

每个贴图块：

```
GBIX(12 B) = 'GBIX' + u32(4) + u32(vram=0)
PVRT(16 B) = 'PVRT' + u32(size) + u32(fmt) + u16(w) + u16(h) + 数据
数据长度   = PKF 对应那块「减去尾部 4 字节填充」
```

网格节点里 `+12` = 贴图索引（0..n-1，必须按序），`+8` = VRAM 地址（`0 / 0x8020 / 0x10040 / 0x12060 / 0x16080 / 0x180a0`），**这两个字段不需要改**。

### 我踩的两个坑（代价是两次实机花屏）

1. **偏移表的基准**：一开始按「表头之后」算，首块写 0 → 全错。正确是**以 TXT7 起点**为基准，首块 = 84。
2. **PKF 的 4 字节尾部填充**：PKF 块比 PVRT 数据多 4 字节填充，拼的时候没削掉，6 块累计 +24 B，整段偏移全错位。

拼出来的文件是 232,268 B（比成品 232,244 B 多 24 B），实机依旧幻彩 —— 差异就来自上面这 24 字节。

## 4. AFS 取料：对手侧的索引公式

对手模型全在 `SCENE\04\NPC\HUMANS.AFS`（CD4 版 160,126,976 B）。

```python
头 u32 = 2010 = 1005 × 2            # item 数
item 2n     = PAKF（贴图包）
item 2n+1   = PAKS（CHRM，网格正文）
代号 = HUMANS.IDX[4 + n*4 : 4 + n*4 + 4]
```

## 6. 对手侧：11 格的换人链与文字

### 6.1 换谁

各格对应的 `SFxx.EV3` 里改角色代号，引擎就会去 `HUMANS.AFS` 取对应 item。12 格（斗牛）是**引擎硬编码**在 1736/1737，试了四次（换代号、换 AFS、换 TGLB/QFRR）全部无效，已封案。

### 6.2 选人界面头像（`SPRITE\OMAKE.SPR`）

- 槽位映射（`OMAK.EV1` `+0x10`）：1→tex24、2→tex25、3→tex29、4→tex30、5→tex28、6→tex27、7→tex26、8→tex32、9→tex31、10→tex33、11→tex34、12→tex24（与 1 格共用）、0→tex35。
- 内容框：tex24~30 = (52,52)-(202,202) 150×150；tex31~49 = (52,42)-(202,216) 150×174。
- 编码：**ARGB4444 + 2×2 VQ**（码本 256×8B @P+16、索引图莫顿序 @P+2048、alpha 全写 0xF000 不透明）。
- `OMAKE.SPR` 尺寸保持 **1,375,432 B** 不变。

踩坑记录（三版才定稿）：

| 版本 | 做法 | 结果 |
|---|---|---|
| v1 | 整张立绘（含灰卡片 + 编号条）contain 贴入 | 框内大片黑、人物偏窄 |
| A 版 | 自身模糊铺底 | 可用但糊 |
| B 版 | 胸像铺满 | 头发与灰底太近，抠图吃掉头顶 |
| **C 版（定稿）** | 连通域抠图 + 原版同槽还原图模糊铺底 + 人物按框高整身居中 | 正常 |

C 版抠图参数：背景色取边框像素中位数，欧氏差 > 26，栈式 BFS 保留最大连通块；铺底用原版同槽还原图（旋转 90 后裁内容框）高斯模糊 10 / 亮度 0.5 / 饱和度 0.85。

### 6.3 名字与说明（`SCENE\04\OMAK\OMAK.EV1`）

- 文本区 `@0x52D0`，13 条 × `0x28`；`+0x18` 流派 / `+0x1C` 人名 / `+0x20` 说明。
- 指针值 = `0x0C328000 + 文件内偏移`；槽容量 = 下一条指针 − 本条指针 − 2，**可以不等长覆盖**。
- `rec12` 与 `rec1` 共用同一组字符串指针 —— 改 1 格会连带 12 格。

### 6.4 加字：三份字库必须同步

中文说明需要新字（本次是「幫」）时：

1. 在字库新开码位：本次取 **A8A3**（24×15、45 B/字、每行 3 字节低位在前）。
   选码位前要在全盘查引用数 —— 原本想用 A8A1，结果 `1ST_READ.BIN` 里出现 8 次，只能弃用。
2. 同一个字同步写进三份：`MISC\DC_KANJI.FON`、`MISC\COLD.BIN`（内嵌字库 @18592 起 351,270 B）、`MISC\RYOU.FON`。
   少一份就会出现「菜单里显示、对话里豆腐块」。

## 7. 标题副标题：烘焙进位图

副标题不在文本区，而是**画进 `SPRITE\TITLE.GZ` 的 1024×512 位图**（存储向 512×1024、9 级莫顿、ARGB1555）。

- 底图必须用**日版原盘的干净 `TITLE.GZ`**：已出过盘的树里那张已带旧副标题，擦不掉。
- 画字参数：`y=352`、`msyhbd 30px`、阴影 `(25,12,4)` / 填充 `(255,226,176)` / 描边 `(70,30,12)`，按宽度居中。
- 小坑：行赋值时必须把两边都摊平成 1-D，2-D 会 shape mismatch。

已出过的标题：`VR戰士 孩童版` / `VR戰士 孩童版・幻彩` / `和泉幻彩格斗版` / `孩童和泉幻彩格斗版` / `莎木和泉格斗版`。

## 8. 出盘：overlay + rebuild

不重建 ISO，只把要改的文件叠上去：

```
buildgdi.exe -rebuild -data <overlay目录> -ip <IP.BIN> -output <输出目录> -gdi <底盘 disc.gdi>
```

- 成功判据：stdout 含 `Done!`；三轨尺寸 `29,846,880 / 1,648,752 / 1,185,760,800`。
- 重建前**必须先关模拟器**，否则旧轨被占用、目录删不干净（会残留 89 B 的 `disc.gdi` + 三轨）。
- 每个盘 1.13 GB，注意空间。

## 9. 追加：汉化版 CD1 的 cdi 原位换主角

汉化版 CD1 是**自启动裁剪镜像**（`IP.BIN` 1,265,664 B、`1ST_READ.BIN` 500,704 B、`STREAM\*.AFS` 与 `HUMANS.AFS` 都被裁小），用 gdibuilder 重建必然打乱启动链。改用**原位扇区补丁**：换零件不换壳。

### 9.1 容器结构

- 文件头 256 字节全零，没有标准 DiscJuggler 版本号。
- 数据扇区**步长 2336 字节**（Mode 2 Form 1 去掉 12 字节同步 + 4 字节头）：每扇区前 2048 字节就是 ISO 文件数据，后面是 EDC/ECC。
- 镜像内偏移公式：`offset = 0x8c491b8 + (LBA - 74060) * 2336`。

### 9.2 三个目标的实际位置

| 文件 | 目录项偏移 | LBA | 原长度 | 换成 |
|---|---|---|---|---|
| `SCENE\01\MODEL\CHARA\RYO_M.MT7` | `0x4176a4` | 74060 | 291,824 | 232,244 |
| `SCENE\01\MODEL\HAND\RYO_TL.MT7` | `0x4199d6` | 81144 | 68,280 | 63,800 |
| `SCENE\01\MODEL\HAND\RYO_TR.MT7` | `0x419a04` | 81178 | 68,280 | 63,768 |

### 9.3 步骤

1. 复制 cdi；
2. 按 2336 步长把新模型逐扇区写进原区间（只写新长度，不补零）；
3. 同时把 ISO 目录项 size 改成新长度（`rec+10` 小端、`rec+14` 大端，两处都要改）；
4. 回读三件套逐字节一致 → Flycast 正常过标题。

这样做的好处：启动链、TOC、文件顺序全都没动，风险为零。
